# راهنمای بیلد — اپ نصبیِ «حسابدار مدیر ساختمان توی‌دید»

این پوشه، پوستهٔ **Electron** است که سرور موجود (`../برنامه (دست نزنید)/server.js`) را به‌صورت اپ نصبیِ مک/ویندوز بسته‌بندی می‌کند. کدِ مالی دست‌نخورده می‌ماند؛ Electron فقط ابزار بیلد است.

> ⚠️ **منبع حقیقتِ کد:** پوشهٔ `برنامه (دست نزنید)`. هرگز مستقیم در `desktop/srv/` ویرایش نکن؛ `srv/` با `npm run sync` از منبع بازساخته می‌شود.

---

## پیش‌نیازها
- **Node.js 22+** و **npm**
- برای ساخت `.dmg`: **مک** (نصب `.dmg` روی مک انجام می‌شود)
- برای ساخت `.exe` ویندوز: روی مک مستقیم **کار نمی‌کند**؛ از **GitHub Actions** (بخش پایین) استفاده کن

## ساختار پوشه
```
desktop/
├── main.js                 پوستهٔ Electron (سرور را با fork بالا می‌آورد)
├── package.json            تنظیمات electron-builder
├── sync.mjs                کپی کد از «برنامه (دست نزنید)» → srv/
├── build/
│   ├── make-icon.mjs       سازندهٔ آیکن (Node خالص، بدون وابستگی)
│   └── icon.png            آیکن ۱۰۲۴×۱۰۲۴ (با اسکریپت بالا ساخته می‌شود)
├── .github/workflows/build.yml   بیلد خودکار مک+ویندوز روی تگ
└── srv/                    ← ساختهٔ sync (در گیت کامیت می‌شود، ولی srv/data و srv/uploads نه)
```

## دستورها
```bash
cd desktop
npm install            # نصب electron + electron-builder (~۲۵۰MB، یک‌بار)
npm run icon           # ساخت/به‌روزرسانی آیکن (اختیاری؛ icon.png از قبل هست)
npm run start          # تست فوری در حالت توسعه (بدون بسته‌بندی)
npm run dist:mac       # ساخت .dmg → پوشهٔ dist/
```
`npm run start`/`dist:*` خودشان اول `sync` را اجرا می‌کنند تا `srv/` تازه بماند.

## مسیر دادهٔ کاربر (بحرانی)
در حالت نصبی، داده هرگز داخل پوشهٔ برنامه نوشته نمی‌شود (فقط-خواندنی است). `main.js` این‌ها را ست می‌کند و `server.js` رعایتشان می‌کند:
- `HS_PACKAGED=1`
- `HS_USER_DIR=<userData>`

مسیرهای واقعی (Electron از `productName` لاتین استفاده می‌کند، نه نام فارسی — تست‌شده روی مک):
- مک: `~/Library/Application Support/Hesabdar Sakhteman ToyeDid/`
- ویندوز: `%APPDATA%\Hesabdar Sakhteman ToyeDid\`

از منوی برنامه: **پرونده ← پوشهٔ داده‌ها** همین مسیر را باز می‌کند (خودکار از `app.getPath('userData')`). حذف برنامه، این داده را پاک نمی‌کند (`deleteAppDataOnUninstall:false`).

> نکته: چون مسیر داده لاتین است، مشکلِ کدپیجِ نام فارسی روی ویندوز پیش نمی‌آید.

## نگاشت نسخه (اجباری در هر انتشار)
`version.json` با `v1.0XX` و `package.json` با `semver` کار می‌کنند. در هر انتشار دستی این نگاشت را رعایت کن:
`v1.009` → `"version": "1.0.9"`. (electron-updater فقط با semver کار می‌کند.)

## امضای کد — انتظار درست
گواهی امضا نداریم (تحریم). پس:
- **ویندوز:** پیام SmartScreen «Windows protected your PC» → کاربر `More info → Run anyway`.
- **مک:** Gatekeeper → کاربر راست‌کلیک → Open، یا `System Settings → Privacy & Security → Open Anyway`.

در صفحهٔ دانلودِ toyedid.com یک راهنمای کوتاه «چطور نصب کنم» بگذار.

## بیلد ویندوز با GitHub Actions
1. یک مخزن گیت با **ریشهٔ همین پوشهٔ `desktop/`** بساز (خودکفاست؛ `srv/` کامیت می‌شود).
2. در `package.json` بخش `build.publish.owner` مقدار `CHANGE_ME` را به یوزر/سازمانِ گیت‌هابت تغییر بده.
3. یک تگ `v...` پوش کن → ورک‌فلو `build.yml` روی مک و ویندوز بیلد می‌کند و نصب‌کننده‌ها + `latest*.yml` (لازم برای آپدیت خودکار) را در Releases می‌گذارد.
- `CSC_IDENTITY_AUTO_DISCOVERY:false` جلوی تلاش برای امضا را می‌گیرد.

## قبل از انتشار — تست‌های پذیرش
مطابق بخش ۷ سندِ «دستورکار-ساخت-اپ-Electron.md» عمل کن. تا وقتی **P1** (نبود خطای `node:sqlite`)، **P4** (ماندگاری داده بعد از ری‌استارت)، **P6** (ننوشتن در پوشهٔ کد) و **P14** (نبود پروسهٔ زامبی) پاس نشده‌اند، سراغ ساخت نصب‌کنندهٔ نهایی نرو.

## مهاجرت دادهٔ فعلی کاربر
دادهٔ واقعی در `برنامه (دست نزنید)/data/sakhteman.db` است. **کپی دستیِ فایل db را پیشنهاد نکن.** به‌جایش:
1. نسخهٔ قدیمی (`.command`) را اجرا کن → تنظیمات ← پشتیبان‌گیری ← دانلود بکاپ.
2. اپ نصبی را باز کن → تنظیمات ← بازیابی از فایل → همان zip.
3. **اعتبارسنجی:** گزارش «تراز کل» و موجودی صندوق‌ها/طلب مدیر در دو نسخه باید عدد به عدد یکسان باشد.
